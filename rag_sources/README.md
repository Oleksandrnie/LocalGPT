# LocalGPT RAG sources

Эта папка хранит локальные документы для RAG. Файлы внутри профильных папок являются runtime-данными и не должны попадать в git.

## Как устроены папки

- Каждый профиль получает свою папку: `profile_<id>_<name>`.
- При смене профиля используется только RAG-папка активного профиля.
- Новый профиль начинает с пустой RAG-папки.
- При удалении профиля его RAG-папка удаляется.

## Как добавлять файлы

Открой UI -> `RAG` -> `Добавить файлы` -> выбери `.md`, `.json` или `.txt` -> `Индексировать`.

После изменения файлов нужно снова нажать `Индексировать`. Если нужно полностью пересобрать embeddings, нажми `Переиндексировать всё`.

## MD + JSON

Рекомендуемый формат для важных знаний:

- `.md` — человекочитаемое объяснение.
- `.json` с тем же именем — источник истины для модели.

Пример пары:

- `third_party.kb.pricing.md`
- `third_party.kb.pricing.json`

Если JSON и Markdown конфликтуют, модель должна использовать JSON. Это правило добавляется в prompt при сборке RAG-контекста.

## Когда достаточно только MD

Для общих текстов, инструкций, описаний, шаблонов и заметок можно добавить только `.md`.

При индексации LocalGPT автоматически создаст рядом базовый `.json`:

```json
{
  "schema": "localgpt.rag.structured.v1",
  "generated_by": "localgpt_auto_structurer",
  "source_file": "example.md",
  "facts": [],
  "constraints": [],
  "sections": []
}
```

Авто-JSON помогает слабой локальной модели видеть структуру: заголовки, bullets, `ключ: значение`, ограничения и важные правила.

## Когда лучше делать JSON вручную

Ручной JSON нужен для данных, где ошибка опасна:

- тарифы, цены, часы, ставки;
- SLA, сроки реакции, приоритеты;
- правила продаж и договорённости;
- списки услуг;
- роли, регламенты, ограничения;
- любые таблицы и иерархии, где модель может смешать значения.

Если рядом с `.md` уже есть `.json`, LocalGPT не перезаписывает его автогенерацией. Это защищает ручной source of truth.

## Рекомендуемый JSON-шаблон

```json
{
  "schema": "localgpt.rag.source.v1",
  "source_file": "example.md",
  "source_of_truth": true,
  "title": "Короткое название",
  "entity": "third_party",
  "facts": [
    {
      "type": "fact",
      "name": "Название факта",
      "value": "Точное значение",
      "notes": "Необязательно"
    }
  ],
  "rules": [
    "Если этих данных нет в JSON, не придумывай.",
    "Если JSON конфликтует с Markdown, JSON прав."
  ],
  "constraints": [
    "Что нельзя смешивать или переносить между категориями."
  ]
}
```

## Пример для тарифов

```json
[
  {"line": "Базовый", "hours": 3, "price": 9990},
  {"line": "Базовый", "hours": 5, "price": 16950},
  {"line": "Базовый", "hours": 7, "price": 23730},
  {"line": "Оптимальный", "hours": 8, "price": 23920},
  {"line": "Оптимальный", "hours": 11, "price": 32890},
  {"line": "Оптимальный", "hours": 15, "price": 44850},
  {"line": "Максимальный / Премиальный", "hours": 16, "price": 47840},
  {"line": "Максимальный / Премиальный", "hours": 24, "price": 71760},
  {"line": "Максимальный / Премиальный", "hours": 40, "price": 119600}
]
```

Для тарифов лучше держать именно массив точных записей: модель хуже путает линейки, часы и цены.

## Практическое правило

Если файл просто объясняет контекст, пиши `.md`.

Если в файле есть точные числа, статусы, правила, тарифы, сроки или “нельзя перепутать”, делай пару `.md + .json`.

Если не хочется писать JSON вручную, можно сначала добавить `.md`, дать LocalGPT создать авто-JSON, потом проверить и при необходимости отредактировать `.json`.
